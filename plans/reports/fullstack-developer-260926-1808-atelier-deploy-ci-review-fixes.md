## Fixes

**M1 (maintenance marker).** `stop` now `touch`es `$DIR/maintenance` before bringing the container down; `apply` checks it right after taking the lock and refuses with exit 75 and a logged reason while it exists; `start` removes it only after `up && healthy` succeeds. The guide's new "Maintenance mode" section documents `gh workflow disable/enable deploy.yml` around any procedure that needs Atelier down for a while.

**M2 (size cap and cleanup).** A new `size_from_registry()` queries `docker buildx imagetools inspect --raw` (reusing the throwaway config's session) for the linux/amd64 manifest and sums `.layers[].size + .config.size` with `jq`, before the pull; going over the cap rejects immediately, no pull attempted. If that check fails for any reason (buildx or jq missing, network hiccup), deploy.sh logs that fact and falls back to the existing post-pull `docker image inspect` check, which remains as the backstop. A new `reject_pulled()` removes `$IMAGE@$digest` before exiting on any check that runs after the pull (revision label, volumes, size backstop). `prune()` now also runs unconditionally at the end of `apply` (success or failure path alike, using whatever the tag files say afterward), guarded by `|| log "prune failed (ignored)"`, and sweeps this repository's own dangling (untagged) images via a second, independent `docker image ls --filter dangling=true` pass.

**M3 (malformed-command tests).** Every case in `test_rejects_malformed_commands` now sends a valid token and registry user on stdin and asserts the literal final message (`rejected: unexpected command`), not just the exit code — so a case that slipped past the grammar would be caught calling `docker login`, not incidentally rejected by empty stdin. Added: a 41-hex SHA, `sha256:<64 hex>x` (one trailing character), a newline-suffixed command, and a leading space. 12 cases total (was 8).

**M4 (test gaps).** Added: stale-loops rollback (a stub `curl` reporting the right version but `"loops":"stale"`); real lock contention (`fcntl.flock` on the actual lock file, held externally, asserting exit 75 and no `up` call); a realistic prune scenario (five tags plus a dangling ID, asserting only the two oldest non-protected tags are removed and never a Folio-tagged digest recorded alongside one); the registry token never appearing in any recorded `docker` argv; the size cap pre- and post-pull; a failed manual rollback restoring the current tag; and the exact `systemd-run` arguments (`--unit=`, `-p Type=oneshot`, `--wait`, `--collect`, `--pipe`, `--quiet`, `--setenv=ATELIER_DETACHED=1`).

**L1 (grammar and DIR trust).** The forced-command path now matches the whole `SSH_ORIGINAL_COMMAND` in one shot: `[[ "$SSH_ORIGINAL_COMMAND" =~ ^deploy\ ([0-9a-f]{40})\ (sha256:[0-9a-f]{64})$ ]]`, reading `sha`/`digest` from `BASH_REMATCH`. `$DIR` on that path is derived from `dirname "$0"`, never from `$ATELIER_DEPLOY_DIR` — stronger than just "ignore the variable when SSH_ORIGINAL_COMMAND is set" (which the finding asked for): there is now no environment variable at all that a forced command's path could be redirected through, regardless of any future sshd misconfiguration. The manual (argv) path is unaffected and still honors `ATELIER_DEPLOY_DIR` (needed for the hermetic tests; a root operator's own shell isn't a trust boundary). The guide's audit command now greps `sshd -T` for `acceptenv` and `permituserenvironment` too, with a note on why they matter for this specific trust argument.

**L2 (compose/prune logging).** `up()` and `stop`'s `dc down` now pipe their output through `logger -t atelier-deploy` (pipefail keeps the wrapped command's exit status, since logger essentially never fails). `prune`'s call site uses `|| log "prune failed (ignored)"` instead of `|| true`; the comment now explains that this covers both the benign "nothing to prune" pipeline quirk *and* a genuine failure, which `|| true` would have hidden either way.

**L3 (compose invocation).** Added `dc() { docker compose -f "$DIR/compose.yaml" -p atelier "$@"; }`; every remaining `docker compose` call goes through it (verified: `grep -n "docker compose" deploy/deploy.sh` shows exactly one hit, inside `dc()` itself).

**L4 (detachment and signals).** `systemd-run` now runs with `-p Type=oneshot` (in addition to `--wait --collect --pipe --quiet`). A `trap 'log "interrupted by signal"; exit 1' TERM HUP INT` runs for the whole script. `stop`, `start` and `rollback` are now detached exactly like `apply`: a single `detach()` helper, called from a unified check right after the verb is parsed (guarded by `$ATELIER_DETACHED`, which the transient unit's own clean environment never has, so there's no infinite recursion), replaces the old `deploy)`-only inline `exec systemd-run …`.

**L5 (egress unit, in part).** Rewritten with one `ExecStart=`/matching `ExecStop=` pair per rule (so a failed rule fails the unit instead of being masked by a later rule that happens to succeed), each using `iptables -w`. Two rules added: `-s 172.30.90.0/24 -o tailscale0 -j DROP` in `DOCKER-USER`, and an `INPUT` rule dropping `-s 172.30.90.0/24 -d 100.64.0.0/10`. `After=docker.service` is unchanged; the guide documents the brief boot-time window as an accepted residual risk.

**L6 (build supply chain).** `docker/build-push-action` now gets `context: .` explicitly (a git-context build can silently ignore `.dockerignore`). I kept `docker/setup-buildx-action` rather than dropping it — I can't run an actual build to confirm the default `docker` driver can push in this exact GitHub-runner/Docker-version combination, and Folio's own reference workflow uses the same setup-buildx-action + build-push-action pairing — and pinned its underlying builder image by digest: `driver-opts: image=moby/buildkit@sha256:28a898719c18a33f4e8000685287fa36fd0dd9560c6440227d3a732d79bb41d8` (the digest of `moby/buildkit:buildx-stable-1`, the tag setup-buildx-action defaults to, looked up read-only via the Docker Hub registry API).

**L8 (image and dependency hygiene).** The Dockerfile's final `COPY --from=build /app /app` (which also copied `pyproject.toml` and `uv.lock`, left over from the build stage) is now two explicit copies: `.venv` and `atelier` only. Added `.github/dependabot.yml` for the `docker` and `github-actions` ecosystems, weekly.

**L9 (test hygiene).** Added a genuine broken-pipe test using a pipe whose read end is closed before the process starts (SIGPIPE on every write), alongside the existing closed-fd (EBADF) test — kept, not replaced, since it's still a valid, distinct scenario. Token rotation is now: create the new token → attach it to the Access application's Service Auth policy (not automatic) → update `ATELIER_PLUGIN_CLIENT_ID` in `.env` (the Client Secret is never server-side; it belongs only in the plugin's own config) → update the plugin's own config → `deploy.sh start` → revoke the old token. I want to flag one specific bug I found and fixed *in my own test harness* while chasing why `prune`'s dangling-sweep test only caught one of two expected removals: my stub `logger`'s `cat >/dev/null` was draining stdin unconditionally, and since `log()` runs inside `prune()`'s `while read -r old; do … done` loop body (sharing that loop's stdin — the `awk` pipe), it was silently stealing the next tag meant for the loop's next `read`. Real `logger` only reads stdin when no message argument is given (which is exactly how `log()` calls it — always with a message), so this was purely a test-double bug, not a real deploy.sh defect; the fix (check for `--` before falling through to `cat`) is in the report's L9/M4 sections above.
